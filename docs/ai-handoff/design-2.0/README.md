# Handoff: Sonix UI 2.0 — переработка интерфейса прошивки Sonix Player

## Обзор
Полная переработка UI/UX прошивки Sonix Player (база — сборка 1.2.5) для карманного плеера с экраном 480×800 (R1) и 480×720 (R3 Pro II). Цели:
- единые правила взаимодействия на всех экранах (тап, свайпы, удержание, нижний лист, тост с отменой);
- «атмосфера» без тяжёлой графики: окраска экрана в тон обложки, плоские цвета, без размытия и теней;
- видимость звуковой цепочки (файл → кодек → наушники);
- настоящая очередь воспроизведения, мини-плеер на всех экранах;
- мгновенное окрашивание экранов за счёт кэша тона и миниатюр обложек.

## О файлах дизайна
`prototype/Sonix UI 2.0.dc.html` — **дизайн-референс в HTML**, а не код для переноса. Это кликабельный прототип, показывающий внешний вид и поведение. Задача — **воссоздать его в существующей кодовой базе прошивки** (C + LVGL) по её паттернам. Открывается в браузере (рядом должен лежать `support.js`). Левая панель прототипа — служебная: переключение темы, устройства, состояния плеера, режима обложек и прыжки к экранам. Правая панель — список принципов и матрица жестов.

`reference/sonix-ui-1.2.5-description.md` — описание текущего интерфейса 1.2.5 (структура экранов, токены, Lucide-иконки, шрифт MiSans). Всё, что не переопределено здесь, остаётся как в 1.2.5.

`sonix_ui_tokens.h` — все размеры, тайминги, пороги жестов и цвета в виде констант C.

## Точность
**Hi-fi** по размерам, цветам, таймингам и поведению. Не финальны:
- значки — текстовые глифы-заглушки → брать Lucide из 1.2.5 (соответствие ниже);
- шрифт Noto Sans → в прошивке MiSans; моно-строки (кодек, сеть) — любой компактный моно-шрифт или MiSans с табличными цифрами;
- обложки и иллюстрации плиток — заглушки (полосатые плашки в тоне альбома).

## Платформенные ограничения (обязательно)
- RGB565, без GPU, одно ядро MIPS → **нет** размытия, теней, полупрозрачных полноэкранных затемнений, горизонтальных/диагональных градиентов.
- Градиент только вертикальный и только на статичных экранах (плеер, страница альбома): **предрендер в полосу 1×H с дизерингом один раз на трек**, дальше растягивать как bg-картинку по ширине.
- Анимации — только сдвиг (`lv_scr_load_anim(..., LV_SCR_LOAD_ANIM_MOVE_*, 180, 0, false)`, `lv_anim` по `translate_x/y`), без анимации прозрачности.
- Слои: поверхность светлее фона + волосяная линия 1 px по верху листа и мини-плеера (тёмная тема — белый 16 %, светлая — чёрный 12 %).

## Принципы взаимодействия (единые для всех экранов)
1. **Край — навигация, содержимое — действия.** Свайп от левого края (зона 22 px, порог 70 px) — «назад». Свайп по строке — действие над строкой.
2. **Тап — главное действие, отклик мгновенный.** На нажатие сразу меняется заливка (`press`), без анимации. Тап по строке трека, радио, Яндекс-трека или книги — **всегда играть**.
3. **У действия одно место.** Свайпы по строке — только очередь: **→ «Следующим», ← «В конец очереди»**. Избранное — только видимая кнопка ☆ в строке (без жеста). В очереди ← — «Убрать».
4. **Удержание (450 мс) → нижний лист** с полным меню объекта — для тех, кто не знает жестов.
5. **Одно меню на всё — нижний лист.** Заменяет поповеры, диалоги, страничные меню. Один объект на `lv_layer_top()`, без затемнения экрана. Пункты 64 px, разрушительные — красным.
6. **Изменение — тост с «Отменить»** (3,5 с, полоска обратного отсчёта). Подтверждение — только для необратимого (очистка кэша). Сканирование стартует сразу, без подтверждения.
7. **Вниз — свернуть верхний слой**: плеер, лист, цепочка звука, тост. Плеер и лист идут за пальцем. Пункт управления (открыт сверху) закрывается свайпом вверх.
8. **Звук виден всегда**: цепочка в мини-плеере и на плеере, тап раскрывает подробности. Янтарный — кодек не тот (например, AAC вместо LDAC).
9. **Плашка = «активно сейчас»**: тонированная поверхность только у играющей строки, подключённых наушников, текущей Wi-Fi сети.
10. **Без дублей**: кнопки в шапке, повторяющие плитки (☺ в «Альбомах», ⚙ в «Музыке»), убраны.

### Матрица жестов
| Объект | Тап | → | ← | Удержание / вертикаль |
|---|---|---|---|---|
| Трек | играть | следующим | в конец | лист |
| Альбом | открыть | следующим | в конец | лист |
| Яндекс-трек | играть | следующим | в конец | лист |
| Строка в очереди | играть | — | убрать (кроме текущей) | лист |
| Радио, книга | играть | — | — | — |
| Исполнитель / жанр / год | открыть | — | — | — |
| Мини-плеер | плеер | пред. | след. | ↑ — плеер |
| Плеер (обложка) | пауза | пред. | след. | ↓ — свернуть |
| Лист, тост | пункт | — | — | ↓ — закрыть |
| Пункт управления | — | — | — | ↑ — закрыть |
| Левый край | — | назад | — | — |

Пороги: захват строки 10 px по горизонтали (если |dx| > |dy|), срабатывание 100 px, максимум сдвига 160 px, возврат 150 мс. Захват вертикали 12 px; плеер сворачивается после 110 px, лист — после 80, тост — после 30. Под строкой при сдвиге видна подложка: → — цвет акцента и подпись «⇥ Следующим»; ← — `SWIPE_L` и «＋ В конец очереди» (в очереди — красная `#E01B24` и «✕ Убрать»).

**Конфликт со скроллом в LVGL:** список скроллится вертикально; строка обрабатывает `LV_EVENT_PRESSING` и по `lv_indev_get_vect()` решает направление после 10 px. При горизонтальном захвате — `lv_indev_wait_release()`-подобная блокировка скролла родителя (снять `LV_OBJ_FLAG_SCROLLABLE` на время жеста или `lv_obj_clear_flag(row, LV_OBJ_FLAG_SCROLL_CHAIN_HOR)`).

## Модель состояния
```
theme: dark|light            accent: cover|blue|orange|yellow|green|purple|pink
tint: bool (окраска от обложки, вкл)   big_rows: bool
nav_stack: [screen_id + arg]           // arg: исполнитель, жанр, десятилетие
queue: [track_id...], qpos: int        // текущий = queue[qpos]
ext: null | {title, artist, hue, live, book}   // радио, Яндекс, книга — вне очереди
paused, pos_s, repeat: off|all|one, sleep: 0|15|30|60|-1(конец трека)
idle: bool                             // ничего не играло с момента установки
bt_on, codec: auto|LDAC|AAC|SBC, ldac: 990|660|330|ABR
sheet: null | {kind, target}           // track|album|qrow|queue|yandex|np|sleep|sort|confirm
toast: null | {text, undo_cb}          // undo_cb восстанавливает снимок
```
**Очередь:**
- Тап по треку в списке — очередь = этот список (порядок экрана), `qpos` = позиция трека.
- «Следующим» — вставка после `qpos` (дубликаты из хвоста убираются).
- «В конец» — добавление в хвост.
- Удаление и перенос — с отменой (снимок `queue`/`qpos` до действия).
- ⏮ в первые 3 с — предыдущий трек, позже — к началу трека.
- Конец трека: повтор одного → заново; конец очереди без повтора → пауза; «Таймер сна: конец трека» → пауза.
- Текущий трек из очереди не убрать.

**Внешнее воспроизведение** (радио / Яндекс / книга) — `ext`. Очередь сохраняется: «Очередь» показывает «Сейчас играет X — вне очереди», ⏭ возвращает в очередь. У прямого эфира нет перемотки, вместо времени — «Прямой эфир».

**Пустое состояние** (`idle`):
- мини-плеера нет, списки получают +88 px;
- на «Главной» и в «Музыке» на месте мини-плеера стоит карточка «⤮ Перемешать всю музыку · N треков»;
- «Очередь» показывает «Ничего не играет» с той же кнопкой.

После остановки или перезагрузки — мини-плеер на паузе с последним треком и позицией.

## Цвет
Палитра экрана строится из **одного оттенка `h`** — тона обложки играющего трека, а на странице альбома — тона этого альбома. Значения `{L, C}` — в `sonix_ui_tokens.h` (`SX_T_*`). Нейтральная палитра (окраска выключена) — `SX_D_*` / `SX_L_*`. Пересчитывать при смене трека или экрана, около 20 цветов; это микросекунды.

```c
/* OKLCH → RGB565 (Björn Ottosson, OKLab) */
static uint16_t sx_oklch_to_565(float L, float C, float h_deg) {
    float h = h_deg * 0.01745329f, a = C * cosf(h), b = C * sinf(h);
    float l_ = L + 0.3963377774f*a + 0.2158037573f*b;
    float m_ = L - 0.1055613458f*a - 0.0638541728f*b;
    float s_ = L - 0.0894841775f*a - 1.2914855480f*b;
    float l = l_*l_*l_, m = m_*m_*m_, s = s_*s_*s_;
    float r =  4.0767416621f*l - 3.3077115913f*m + 0.2309699292f*s;
    float g = -1.2684380046f*l + 2.6097574011f*m - 0.3413193965f*s;
    float bl= -0.0041960863f*l - 0.7034186147f*m + 1.7076147010f*s;
    #define GAM(x) ((x) <= 0.0031308f ? 12.92f*(x) : 1.055f*powf((x), 1/2.4f) - 0.055f)
    #define CL(x)  ((x) < 0 ? 0 : (x) > 1 ? 1 : (x))
    r = CL(GAM(r)); g = CL(GAM(g)); bl = CL(GAM(bl));
    return ((uint16_t)(r*31+.5f) << 11) | ((uint16_t)(g*63+.5f) << 5) | (uint16_t)(bl*31+.5f);
}
```

Акцент «от обложки» по умолчанию; шесть пресетов из 1.2.5 — альтернатива. Плеер, мини-плеер и страница альбома всегда тёмные, независимо от темы.

## Компоненты (строить один раз)
- **Строка** (`sx_row`): миниатюра / номер / круг, заголовок и подзаголовок, хвост (☆, ›, длительность). Состояния: обычная (прозрачная), нажатая (`press`), играет (`surface` + заголовок акцентом + эквалайзер), сдвинута (подложка). Конфигурация: какие свайпы и есть ли лист.
- **Карточка** (`sx_card`): заголовок, подпись (обычная или моно акцентом), значение справа, шеврон / переключатель, пилюли / образцы цвета / полоса / кнопка-действие. Флаг `active` = смесь 16 % акцента с `surface`.
- **Нижний лист** (`sx_sheet`): один экземпляр на `lv_layer_top()`. Ручка 44×5, заголовок, подпись, пункты 64 px, опционально пара кнопок «Отмена / Действие». Тянется вниз за пальцем.
- **Тост** (`sx_toast`): один экземпляр. Текст, «Отменить», полоска обратного отсчёта 3 px. Можно использовать имеющийся `gui_notify_popup`.
- **Мини-плеер** (`sx_mini`): на `lv_layer_top()`, общий для всех экранов. Скрыт на плеере и в `idle`.
- **Эквалайзер**: 3 столбика 5×22, шаг 3, анимация в 4 шага примерно 10 кадров/с, разный темп; на паузе замирают. Перерисовка области 21×22.
- **Оверлей громкости**: полоса 64×300 у правого края, 1,5 с после нажатия кнопки корпуса.
- **Полоса А–Я + пузырь с буквой.**

## Анимации
- **Вперёд**: новый экран въезжает справа, 180 мс, ease-out. **Назад** — слева.
- **Плеер**: открывается снизу. Сворачивается вниз за 180 мс, потом снимается со стека.
- **Лист**: 200 мс ease-out. Сдвинутая строка возвращается за 150 мс.
- **Без анимации**: прозрачность, цвет фона, изменение размера.

## Обложки: пайплайн
1. При сканировании (обложка встроенная или `folder.jpg`): декодировать JPEG в 1/8 размера (TJpgDec / libjpeg `scale_denom = 8`) и взять самый насыщенный заметный оттенок, а не среднее.
2. В БД (альбом): `cover_h` (u16), `cover_c`, `cover_l` (u8), `cover_mtime`; миниатюры RGB565 56 px (~6 КБ) и 240 px (~115 КБ) — сырые файлы на SD.
3. Нет обложки — оттенок = хеш названия альбома.
4. Не успели при сканировании — фоновая задача с низким приоритетом; пауза на время прокрутки и анимаций; при первом показе — только видимые строки.
5. **UI**: строка сразу рисуется плашкой `SX_T_COVER_TONE`, миниатюра подменяет её. Тон экрана известен до загрузки картинки. На плеере до полной обложки — растянутая миниатюра 240.

В прототипе это переключатель «Обложки: 1.2.5 / Тон / Кэш».

## Порядок внедрения (предложение)
1. **Токены и палитра**: `sonix_ui_tokens.h`, `sx_oklch_to_565`, расчёт палитры при смене трека.
2. **Базовые компоненты**: строка, карточка, лист, тост; перевод существующих экранов на них без смены поведения.
3. **Модель очереди + мини-плеер + новый плеер** (цепочка звука, «Далее», сворачивание).
4. **Жесты строк**, удержание → лист, свайп от края, тосты с отменой во всех изменениях.
5. **Пайплайн обложек** (тон и миниатюры в БД, фоновая задача).
6. **Шлифовка**: градиенты плеера и альбома, эквалайзер, анимации переходов, пустые и ошибочные состояния, сканирование книг с прогрессом.

## Файлы
- `prototype/Sonix UI 2.0.dc.html` — прототип (открыть в браузере вместе с `support.js`). Логика экранов — в классе `Component` внизу файла: `renderVals()` собирает блоки экрана, `mkRow` / `card` — описания компонентов, `chainFor` — цепочка звука, `play` / `step` / `insertNext` / `addEnd` / `removeAt` — очередь.
- `sonix_ui_tokens.h` — константы.
- `reference/sonix-ui-1.2.5-description.md` — исходное описание 1.2.5.
